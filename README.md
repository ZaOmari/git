# СтройКонтроль

Учёт **себестоимости**, расходов и ЗП по строительству частных домов — для
семейного бизнеса из двух равноправных партнёров (Таня — финансы/документы,
Гриша — стройка/материалы). Главная цифра везде — **себестоимость каждого
объекта**.

Это реализация дизайна из Claude Design (`СтройКонтроль.dc.html`) в виде
работающего **PWA** для iPhone: чистый iOS-стиль, русский язык, синий акцент.

## Что внутри

Один навигируемый прототип со всеми экранами из концепции:

- **Объекты** — список с себестоимостью как героем, прогресс к стоимости по
  договору, сводный итог по всем домам, индикатор синхронизации (Т/Г).
- **Объекты** — на сводке две цифры: себестоимость всех домов + **«всего к оплате»**
  (поставщикам + остаток по бригадам, одной строкой), подпись «обновлено только что».
- **Объект** — герой-себестоимость, под ней **полоса заметок**, ниже вкладки:
  - **Полоса заметок** — свёрнутая строка с превью закреплённой (📌) заметки и
    счётчиком «· ещё N»; «+» для быстрой записи; тап раскрывает аккордеон со
    всеми заметками и закреплением (закреплена одна);
  - **Расходы** — категории, оплачено/к оплате, фото чека, делёж между объектами;
  - **Бригады / ЗП** — договорено / выплачено / остаток, несколько выплат;
  - **Этапы** — таймлайн собственных этапов дома + «Сформировать акт»;
  - **Оплаты клиента** — внесения частями, эскроу (только для договорных);
  - **Продажа** — себестоимость / цена / **маржа** (для домов на продажу, без клиента).
- **Быстрый расход** — плавающая кнопка → лист со свободным вводом (сумма + текст,
  необязательная категория, статус, делёж, фото). Сохранение **обновляет
  себестоимость вживую** + тост «Сохранено · видит Таня».
- **Акт приёма работ** — редактируемые реквизиты + **подпись пальцем на canvas**
  → «Сохранить PDF · на почту».
- **Уведомление** при приближении себестоимости к стоимости по договору
  (≥ 85% — оранжевый баннер, ≥ 100% — красный).
- **Демо-тур** — ведёт по сценарию показа (расход → себестоимость → бригады →
  делёж → акт → баннер → заметки). Показывается один раз и **перезапускается
  кнопкой «?»** в шапке.
- **Настройки и управление (⚙)** — отдельный экран, три группы:
  - **Внешний вид** — Тема (Авто по `prefers-color-scheme` / Светлая / Тёмная,
    настоящий тёмный фон) + Размер текста (А/А/А, масштабирует весь UI; база в
    `rem` — уважается и Dynamic Type iOS). Выбор сохраняется.
  - **Управление** — Объекты (создать / изменить / архивировать — скрываются из
    главного списка, но данные остаются / удалить с подтверждением); справочник
    Бригад; редактируемые Категории расходов (подсказываются при вводе); Шаблон
    этапов для новых объектов; Реквизиты исполнителя для актов (заказчик —
    в самом акте).
  - **Данные** — Резервная копия (выгрузка JSON), Печать сводки (PDF), Сбросить
    демо-данные. Партнёры Таня и Гриша показаны списком без разграничения прав.
  - Крупные зоны нажатия (≥48px), подписи у кнопок («Расход», «Выплата», «Акт»),
    контрастный текст. Всё работает при тёмной теме и крупном шрифте.
- **Обновления** — service worker network-first для HTML/JS/CSS (обычный refresh
  подтягивает новую версию при сети; офлайн — из кэша), версионированный кэш с
  удалением старых при активации, авто-перезагрузка один раз при смене версии.

## Запуск

Это статический PWA на нативных ES-модулях — **сборка не нужна**, но его нужно
отдавать по HTTP (модули и service worker не работают с `file://`):

```bash
npm start          # python3 -m http.server 8000
# затем откройте http://localhost:8000
```

Любой статический сервер подойдёт (`npx serve`, `python3 -m http.server`, и т. д.).
На iPhone: открыть в Safari → «Поделиться» → «На экран „Домой“» — установится как
приложение (офлайн-кеш через `sw.js`).

## Структура

```
index.html              каркас рамки + точка монтирования
styles.css              базовые стили, анимации, адаптив (full-bleed на телефоне)
manifest.webmanifest    манифест PWA
sw.js                   офлайн service worker (app-shell кеш)
icons/                  иконки приложения
src/
  app.js                состояние, рендер, обработчики, подпись на canvas, демо-тур
  views.js              шаблоны экранов (точные инлайн-стили из дизайна)
  tour.js               демо-тур (шаги по сценарию показа, перезапуск кнопкой «?»)
  helpers.js            форматирование и расчёты (себестоимость, остатки, маржа, обязательства)
  data.js               сид-данные и константы (этапы, категории, заметки)
```

## Заметки по реализации

- Дизайн-прототип был на React-подобном Design-Component-фреймворке; здесь он
  воссоздан 1:1 на ванильных ES-модулях, чтобы запускаться без зависимостей и
  без шага сборки. Вёрстка и цифры совпадают с исходником.
- Данные — лёгкие, сгенерированные, живут в памяти.

### Что ещё не подключено (заложено в UX, см. концепцию)

- **Supabase** (PostgreSQL, авторизация, хранилище фото/PDF, **realtime** —
  «внёс один, сразу видит другой»).
- Реальная генерация **PDF** актов/выгрузок и отправка на почту.
- Полноценный **офлайн-черновик** расхода с синхронизацией при сети.
- История правок по записи; кабинет клиента (на будущее — §9 концепции).
